# Beam-MP-Server-Manager v0.10.0

Release status: **validated release candidate with known local-appliance regressions**

Date: 2026-08-17

## Release artifact

Validated appliance source artifact:

- `Beam-MP-Server-Manager.ova` (approximately 4.3 GB before split distribution)

The official GitHub Release `v0.10.0` is the primary download point. Because the OVA is too large for the chosen single-asset release workflow, it is distributed as a split 7-Zip archive with parts kept at approximately 1.9 GB maximum:

- `Beam-MP-Server-Manager-v0.10.0.7z.001`
- `Beam-MP-Server-Manager-v0.10.0.7z.002`
- `Beam-MP-Server-Manager-v0.10.0.7z.003`
- `Beam-MP-Server-Manager-v0.10.0-SHA256SUMS.txt`

Users download all three parts into the same directory, open the `.001` part with 7-Zip, extract `Beam-MP-Server-Manager.ova`, then import the OVA into VMware Workstation.

Integrity values must be taken from the generated `Beam-MP-Server-Manager-v0.10.0-SHA256SUMS.txt`; checksums are intentionally not duplicated manually in this document.

The reusable distribution policy is documented in `docs/releases/ARTIFACT_DISTRIBUTION.md`.

## Version identity

The validated appliance reports application version `0.10.0`, matching `pyproject.toml`. The release/tag name for this artifact is therefore `v0.10.0`.

## Validated scope

The exported OVA was produced from a disposable full clone of the validated DEV appliance, sanitized with the canonical factory-image workflow, exported offline, and then imported as a brand-new clean-room VM.

Observed clean-room validation included:

- fresh First Run GUI rather than an inherited user session;
- new machine/network identity and fresh one-time Web pairing code;
- successful first Web administrator creation;
- no previous BeamMP AuthKey, uploaded mods, backups, player/session history or prior Web state;
- fresh BeamMP AuthKey configuration and server startup;
- Gridmap V2 official-map startup;
- real BeamNG/BeamMP client connection;
- Server Live join, vehicle, movement, telemetry/radar and disconnect updates without browser refresh;
- upload/distribution/download/spawn/use of a known-good modded vehicle;
- official BeamNG map thumbnails preserved in the exported appliance;
- modded thumbnail behavior preserved.

The final Windows pytest rerun after the release-contract test correction was reported green with **0 failures**. The exact final pass/skip/warning count was not pasted into the chat, so it is not invented here.

## Post-validation known regressions

After the original clean-room acceptance sequence, several real local-appliance defects were discovered from the exported v0.10 OVA.

### Graphical First Run / reboot

- completing First Run did not reliably trigger the expected automatic reboot;
- the appliance could fall back to the legacy text status console;
- after reboot, the intended LightDM/XFCE `beamconsole` graphical appliance window was not reliably restored.

This means the original v0.10 OVA must **not** be described as a full pass for the local appliance experience, even though its server/Web/BeamNG/mod/telemetry behavior was validated.

The source correction was implemented and runtime-validated on the v0.11 development branch using a fresh disposable OVA test VM. The original exported v0.10 OVA remains historical evidence of the regression and is not silently relabeled as fixed.

### Linux maintenance account skipped by graphical First Run

The v0.10 graphical wizard contains the code and screen for creating a Linux maintenance account, but the normal GUI routing goes directly from keyboard/localization to finalization. As a result, a clean factory-reset appliance can complete graphical First Run with **no regular human Linux account at all**.

This was proven after the v0.11 factory-reset correction: a fresh disposable clone showed no UID 1000-59999 account, and SSH for the expected maintenance user therefore failed before updater validation could begin.

The v0.11 source adds a mandatory account step and a finalization safety gate that verifies the recorded maintenance account exists and has a usable password. Runtime validation of that corrected account flow remains a v0.11 release gate and is tracked by issue #7.

### Factory reset self-termination

A further issue showed that direct factory-image reset over an SSH maintenance session could terminate its own execution context before poweroff. The factory reset helper was changed on the v0.11 development branch to dispatch destructive work through a detached root systemd service, and automatic poweroff was runtime-validated.

## Important release rule

Do not modify a validated OVA in place. Any functional change must go back through source development and runtime validation, then a new disposable clone, sanitize, export and clean-room validation cycle.

For v0.11.0 and later, use the same split-archive naming convention whenever the final OVA still requires multiple GitHub Release assets. The actual number of parts is determined by the final OVA size.

## Known deferred items

Not release blockers for the original v0.10.0 server/Web scope:

- true BeamNG minimap / Big Map projection in Server Live;
- richer BeamMP Direct Connect information display;
- appliance self-update mechanism.

The proven fallback radar remains the supported Server Live position display for this release.
