# Beam-MP-Server-Manager v0.11.0

Release status: **stable - final appliance runtime validation passed**

Target release: v0.11.0 VMware Edition

## Summary

v0.11.0 focuses on making the VMware appliance maintainable after installation while correcting appliance-onboarding defects discovered from the v0.10.0 OVA.

The release also establishes project rules needed for the future native Windows Edition without forking the Web Manager/core.

## User-visible changes

### Manager self-update

A new Manager update area is available in Settings.

It can:

- show the installed Manager version;
- discover the latest official GitHub Release;
- show whether a validated update package is available;
- install the validated latest package with one action;
- accept a local `.update.zip` as a manual fallback;
- show the result of the last update attempt.

Normal update use does not require SSH or a shell.

The first public version containing this mechanism is v0.11.0. The historical v0.10.0 OVA does not contain the updater, so v0.10.0 cannot self-bootstrap into v0.11.0 through the Web UI.

### Automatic rollback

VMware Edition update installation is performed through a narrowly privileged helper.

The updater:

- validates package structure/version/SHA-256 before privileged installation;
- builds the candidate Python environment as the unprivileged Manager account;
- preserves persistent Manager state;
- swaps the installed Manager tree only after staging succeeds;
- restarts the Manager;
- verifies `/api/health` and `/api/appliance/version`;
- automatically restores the previous application/data when the new Manager fails health validation.

BeamMP configuration/AuthKey, mods and BeamMP backups are outside the application swap and are not replaced by a Manager update.

### First Run maintenance account fix

The historical First Run GUI contained a Linux maintenance-account page but normal graphical routing skipped it. This could leave a freshly initialized appliance without the supported Linux maintenance identity.

v0.11.0 changes the graphical flow to:

```text
Language -> Location -> Keyboard -> Linux maintenance account -> Finalization
```

Finalization now refuses to complete unless the maintenance account actually exists and has a usable password.

This is tracked by issue #7 and requires final runtime proof on a disposable appliance before release.

### First Run / local console reliability

Corrections developed after the v0.10.0 OVA regression include:

- automatic reboot after successful graphical First Run;
- permanent graphical XFCE appliance session with `beamconsole` autologin;
- legacy text console disabled from the normal path;
- LightDM configuration hardened for the appliance session;
- graphical baseline/provisioning contract tests.

### Factory reset reliability

The factory-image reset helper now detaches destructive work into a transient root systemd worker before deleting/terminating maintenance accounts. This prevents a direct SSH invocation from killing its own execution context before identity cleanup and automatic poweroff.

The corrected poweroff path was runtime-validated during v0.11 development.

### Bug / feature reporting

The Web UI includes a **Bug / suggestion** action.

It opens a structured form and hands a pre-filled issue to the public GitHub repository for final review/submission.

Optional automatic diagnostics are deliberately limited to non-secret data such as Manager version and safe health status. No GitHub token, BeamMP AuthKey, password, appliance security code, cookie or IP address is automatically attached.

Structured GitHub Bug Report and Feature Request forms are included in the repository.

## Update package / release distribution

The publishable Manager update asset naming convention is:

```text
Beam-MP-Server-Manager-v0.11.0.update.zip
```

with a generated SHA-256 companion file.

The VMware OVA remains a separate release artifact. If its size still exceeds the practical single-asset limit, use the established split archive convention:

```text
Beam-MP-Server-Manager-v0.11.0.7z.001
Beam-MP-Server-Manager-v0.11.0.7z.002
...
Beam-MP-Server-Manager-v0.11.0-SHA256SUMS.txt
```

The actual number of 7-Zip parts depends on final OVA size.

## Security / integrity changes

- updater sudo access is restricted to the named appliance update helper rather than a generic root shell;
- update ZIP and tar payload structure are fail-closed;
- traversal, absolute paths, Windows-drive ambiguity, symlinks and special tar entries are rejected;
- payload size/count limits are enforced;
- inner payload SHA-256 is verified from the manifest;
- official one-click downloads require the exact expected GitHub Release asset and GitHub-published SHA-256 digest;
- final GitHub redirects are restricted to approved GitHub download hosts;
- no GitHub credential is embedded in the appliance;
- update result API exposes only non-secret fields.

## Future Windows Edition preparation

v0.11.0 remains VMware/Linux only. It does **not** implement the native Windows Edition.

Architecture work now formally requires one project, one Web UI and one core with OS-specific runtime backends:

```text
Web UI -> FastAPI/Core -> LocalLinuxBackend
                       -> LocalWindowsBackend [future]
```

New common business logic must avoid direct Linux service-manager/shell coupling. The current Linux-specific coupling and future Windows target are documented in `docs/architecture/WINDOWS_EDITION_PREPARATION.md`.

The future Windows target remains a self-contained installer with Program Files / ProgramData separation, a Windows service supervising `BeamMP-Server.exe`, Windows Firewall setup and a validated/recommended BeamMP version policy.

## CI / validation

GitHub Actions runs the full pytest suite on Linux and Windows with supported Python versions.

Release completion still requires the final runtime sequence on a disposable VMware appliance:

1. fresh/factory-reset First Run shows the maintenance-account page;
2. the selected maintenance account is actually created and SSH-authenticatable;
3. graphical First Run completes and reboots automatically into the appliance desktop;
4. healthy synthetic Manager update installs while preserving state;
5. forced-bad synthetic update triggers automatic rollback;
6. Manager returns healthy on the previous version;
7. one normal reboot preserves the final graphical/runtime state.

Do not change this document to `Release status: released` until that sequence and the final full CI suite pass.

## Known compatibility note for v0.10.0 users

Because v0.10.0 predates the self-update helper, upgrading an existing v0.10.0 appliance to v0.11.0 requires the documented OVA replacement path or an explicit maintenance/bootstrap procedure. Starting with v0.11.0, subsequent compatible Manager releases can use the in-product updater.

## Deferred

Not part of the v0.11.0 release gate:

- native Windows Edition implementation;
- true BeamNG minimap / Big Map projection;
- richer BeamMP Direct Connect information;
- silent unattended Manager auto-update;
- blindly tracking the newest upstream BeamMP Server release.
